Product Requirements Document (PRD) - Revised
Intelligent Logistics Access Control System (ILACS) - Frontend Phase
1. Project Overview
1.1 Project Name

Intelligent Logistics Access Control System (ILACS) - Frontend Module
1.2 Problem Statement

Maritime port access suffers from congestion and lack of visibility. Current booking systems require complex interactions, leading to inefficiencies for carriers and terminal operators. The APCS needs to regulate truck flows through a booking system that manages time slots and terminal capacities while providing simple query interfaces without complex navigation.
1.3 Solution

A modern, role-based web application providing:

    Multi-role logistics portal with distinct interfaces

    Real-time interactive dashboards with animated yard representations

    Intelligent booking and slot management system

    Conversational AI assistant interface

    Comprehensive notification system with priority-based alerts

    QR code-based access validation

1.4 Primary Objectives (Frontend Phase)

    Develop intuitive, role-based user interfaces with clear role separation

    Implement real-time data visualization with animated yard representations

    Create modular, flexible architecture for future enhancements and feature additions/removals

    Establish comprehensive design system with glass morphism effects

    Build mock backend integration for development and testing

1.5 Core Principles

    Modularity: Component-based architecture allowing easy feature addition/removal

    Flexibility: Design that accommodates future changes with minimal disruption

    Real-time: Live updates for terminal status, truck movements, and notifications

    Accessibility: WCAG 2.1 AA compliant with responsive design

    User-Centric: Simplified interfaces reducing complex navigation

2. User Roles & Personas
2.1 System Administrator (Admin)

Access Level: Global system access

Primary Responsibilities:

    User account management (create, disable, modify)

    Terminal assignment to operators

    Super management of terminal states and configurations

    System-wide audit log monitoring and compliance

    Performance analytics and reporting

    Global configuration and system settings

2.2 Terminal Operator (Terminal Op)

Access Level: Terminal-specific (1 terminal per operator)

Primary Responsibilities:

    Real-time terminal monitoring and visualization

    Booking request validation and management

    Terminal capacity management and configuration

    Truck movement tracking within assigned terminal

    Issue resolution and incident reporting

2.3 Carrier/Courier

Access Level: Company-specific access

Primary Responsibilities:

    Slot booking creation, modification, and cancellation

    Fleet status monitoring and management

    QR code distribution to truck drivers

    Booking history and performance tracking

    Self-service status checks via natural language interface

3. Functional Requirements
3.1 Authentication & Authorization Module
3.1.1 Registration Flow

Type: Invite-only system (Admin creates all accounts)

Process:

    Admin creates user account via admin panel with temporary credentials

    System sends invitation email with verification link and temporary password

    User completes email verification process

    User sets permanent password following security guidelines

    Account becomes active and accessible

Required Information (Minimum Set):

    All Users: Full name, email address, phone number

    Carrier: Company name, tax ID, fleet size, business address

    Terminal Op: Assigned terminal, employee ID, shift information

    Admin: Contact details, system role designation

3.1.2 Login System

Method: Simple email/password authentication

Features:

    "Forgot Password" flow with secure email reset

    "Remember Me" functionality (optional)

    Session management using JWT tokens

    Auto-logout after 24 hours of inactivity (configurable)

    Failed login attempt tracking and lockout

3.1.3 Role-Based Access Control (RBAC)

Three-tier permission system:

    Admin: Full system access + user management + global configuration

    Terminal Op: Terminal-specific operations + booking validation + capacity management

    Carrier: Self-service booking + fleet management + status queries

UI Adaptation:

    Dynamic menu items based on role permissions

    Dashboard components customized per role

    Action buttons and features filtered by role

    Data visibility restricted to authorized scope

3.6 QR Code Access System

Generation & Distribution:

    Unique QR code generated upon booking confirmation

    Display Locations: Carrier dashboard, email confirmation, mobile view

    QR Code Features:

        Unique identifier per booking with encryption

        Configurable expiry time (default: 1 hour after slot end)

        One-time regeneration option with invalidation of previous

        Preview modal with booking details and validity period

        Download options: PNG, PDF, SVG formats

Usage Flow:

    Carrier sends QR code to assigned truck driver

    Driver displays QR on mobile device at terminal gate

    Terminal operator scans via gate system (future integration)

    System validates and updates booking status to "consumed"

    Real-time update reflected across all dashboards

// Server → Client Events (Real-time updates)
const SERVER_EVENTS = {
  TERMINAL_UPDATE: 'terminal:update',        // Terminal status changes

  CHAT_MESSAGE: 'chat:message',             // AI chat messages

// Client → Server Events (User actions)
const CLIENT_EVENTS = {
  SUBSCRIBE_TERMINAL: 'subscribe:terminal',     // Subscribe to terminal updates
  UNSUBSCRIBE_TERMINAL: 'unsubscribe:terminal', // Unsubscribe from terminal
  ACK_NOTIFICATION: 'ack:notification',         // Acknowledge notification
  SEND_CHAT_MESSAGE: 'chat:message:send',       // Send chat message
  UPDATE_PRESENCE: 'presence:update',           // Update user presence
};

Browser compatibility issues	Medium	Low	Progressive enhancement, feature detection, polyfills for critical features
State management complexity	High	High	Clear separation of concerns, dedicated stores per domain, comprehensive testing
Animation performance on low-end devices	Medium	Medium	Reduced motion preferences, performance budgets, fallback static views
